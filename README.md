# 🚀Вся база урока

Этот гайд поможет разобраться, как устроен компьютер «под капотом», как пишется код и как программа общается с процессором и памятью.

---

## 1. Бит, байт и коробки с данными (Типы данных)

### Что такое бит и байт
Представь себе обычный настенный выключатель. У него есть только два состояния: **Включен (1)** или **Выключен (0)**. 
* **Бит (bit)** — это и есть один такой выключатель. Это самая маленькая частица информации в компьютере.
* **Байт (byte)** — это коробка, в которой ровно **8 таких выключателей (битов)**. 

Если пощелкать этими восемью выключателями в разных комбинациях (например, `00000000`, `00000001`, `11111111`), то всего можно получить **256 разных комбинаций**. Поэтому в один байт можно записать любое число от 0 до 255.

### Как компьютер видит числа
Компьютер — это просто гигантская гирлянда из выключателей. Он не знает, что такое буква "А" или число "500". Он всё переводит в код из нулей и единиц (двоичную систему):
* **Целые числа** превращаются в двоичный код напрямую.
* **Отрицательные числа**: компьютер договаривается, что самый первый левый выключатель (бит) отвечает за знак. Если там `1` — число отрицательное, если `0` — положительное.
* **Дробные числа (с запятой)**: кодируются хитро, как в научной нотации (например, $1.23 \cdot 10^3$). Компьютер делит биты в коробке на три части: одна отвечает за знак, вторая за само число (мантиссу), третья — за то, на сколько сдвинуть запятую (экспоненту).

### Размерность типов данных (Размер коробок)
В программировании тип данных — это размер коробки, которую мы бронируем в памяти под наше число.


| Тип данных | Размер в байтах | Сколько это в битах | Ассоциация и диапазон |
| :--- | :--- | :--- | :--- |
| **byte** | 1 байт | 8 бит | *Спичечный коробок*. Только положительные числа от 0 до 255. |
| **sbyte** | 1 байт | 8 бит | *Спичечный коробок со знаком*. От -128 до 127. |
| **int** | 4 байта | 32 бита | *Обувная коробка*. Стандарт для чисел. От -2 миллиардов до +2 миллиардов. |
| **long** | 8 байт | 64 бита | *Большой чемодан*. Для гигантских чисел (например, расстояние до звезд в миллиметрах). |
| **double** | 8 байт | 64 бита | *Чемодан с разделителем*. Для дробных чисел с высокой точностью. |

## 2. Битовые операции (Поразрядная магия)

Представь, что мы сравниваем две коробки байт, сопоставляя выключатели друг над другом.

* **AND (И / `&`) — Правило строгого контроля.**
  Лампочка загорится (`1`) только если **оба** выключателя включены. Если хотя бы один выключен — на выходе будет `0`.
* **OR (ИЛИ / `\|`) — Правило доброго вахтера.**
  Лампочка загорится (`1`), если включен **хотя бы один** любой выключатель. `0` будет только если оба выключены.
* **NOT (НЕ / `~`) — Операция «Наоборот».**
  Просто переворачивает значение. Был `1` — стал `0`, был `0` — стал `1`.

### Примеры кода (C#)
```csharp
int a = 5;  // В битах: 0101
int b = 3;  // В битах: 0011

int resultAnd = a & b; // Сравниваем: 0101 И 0011 -> Получаем 0001 (это число 1)
int resultOr  = a | b; // Сравниваем: 0101 ИЛИ 0011 -> Получаем 0111 (это число 7)
```

## 3. Условные операторы и логика (`if`, `while`)

Управленцы в коде — это конструкции `if` (если) и `while` (пока). Они очень прямолинейны. Они не умеют думать, они ждут на вход только один четкий ответ: **boolean** (`true` / Истина или `false` / Ложь). Для них мир черно-белый.

Этот самый `boolean` они могут получить из четырех разных мест:

```csharp
// 1. Из литерала (прямо текстом в коде)
if (true) { 
    // Этот код выполнится ВСЕГДА
}

// 2. Из переменной (флажка)
bool isEngineStarted = true;
if (isEngineStarted) {
    // Код выполнится, так как в переменной лежит true
}

// 3. Как результат работы функции (метода)
if (CheckAccess()) {
    // Функция CheckAccess() внутри себя что-то проверила и вернула true или false
}

// 4. Как результат сравнения (выражения)
int age = 20;
while (age < 18) {
    // Пока age меньше 18 (это выражение дает false, так как 20 не меньше 18), 
    // цикл работать не будет.
}
```


### Разница между if, else if и else
Представь, что ты выбираешь, что надеть по погоде:
```csharp
int temperature = -10;

if (temperature > 20) {
    // Если тепло
    Console.WriteLine("Надень футболку"); 
} 
else if (temperature > 0) {
    // Если первое не подошло, но температура выше нуля
    Console.WriteLine("Надень куртку"); 
} 
else {
    // Если вообще ничего из верхнего не подошло (все остальные случаи)
    Console.WriteLine("Надень пуховик и шарф"); 
}
```
блок else - не обязателен, но если он есть, то это завершение всей цепочки и выполняется в том случае, если все предыдущие условия if(), else if() не сработали

## 4. Что такое программа на самом деле (Взгляд сквозь матрицу)

Когда ты пишешь красивый код на C#, Java или Python — это код для человека, чтобы у нас не кипели мозги. 

Компьютер этот код не понимает. Специальная программа (компилятор) переводит твой код вниз — до уровня **Ассемблера**, а затем и в машинный код (нули и единицы).

**Ассемблер** — это самый примитивный текстовый язык, который напрямую командует процессором. На этом уровне нет никаких "классов", "объектов" и "сложной логики". Программа превращается в пошаговый список тупых микро-команд:
1. Возьми число из коробки памяти А и переложи в карман процессора (регистр) `EAX` -> `MOV EAX, [ячейка_А]`
2. Добавь к числу в кармане `EAX` число 5 -> `ADD EAX, 5`
3. Сравни то, что получилось, с числом 10 -> `CMP EAX, 10`
4. Если получилось меньше, прыгни на 5 строчек назад -> `JL кусок_кода`

Любая сложная игра или сайт «под капотом» — это просто миллиарды таких микро-прыжков и перекладываний чисел из одного кармана в другой.

## 5. Анатомия Класса: Шаблон и Чертеж

**Класс** — это чертеж. Например, чертеж автомобиля. По этому чертежу на заводе можно сделать 100 реальных машин. Реальная машина, сделанная по чертежу — это **объект** (или экземпляр класса).

Внутри класса всё строится по одному простому шаблону-заклинанию:  
👉 **`{тип данных} {название}`**

### Из чего состоит класс:
* **Поля** — это переменные внутри класса. Это *характеристики* объекта. (У машины: `int maxSpeed`, `string color`).
* **Свойства** — это "умные поля". Защитный забор вокруг поля с дверцей. Они позволяют проверять данные перед тем, как их записать или отдать. (Например, не дать записать в поле `age` отрицательное число).
* **Методы** — это функции внутри класса. Это то, что объект умеет *делать*. Наша машина умеет ехать: `void Drive()`.

### Пример кода класса
```csharp
class Car 
{
    // Поле (просто переменная) — шаблон: {тип} {название}
    private int speed; 

    // Свойство — обертка для безопасности поля speed
    public int Speed 
    {
        get { return speed; }
        set { 
            if (value >= 0) speed = value; // Защита: скорость не может быть отрицательной!
        }
    }

    // Метод (функция) — шаблон: {что возвращает} {название}({параметры})
    public void Refuel(int liters) 
    {
        // Метод выполняет действие
        Console.WriteLine($"Заправлено на {liters} литров.");
    }
}
```

### Параметры vs Аргументы (Строгий порядок)
Здесь часто путаются. Запомнить легко:
* **Параметры** — это "приемные карманы", которые мы запрограммировали в методе (в чертеже).
* **Аргументы** — это реальные "вещи" (значения), которые мы туда закидываем при вызове.

> **Правило конвейера:** Аргументы должны подходить по типу данных и идти строго в том же порядке, в каком объявлены параметры!

```csharp
// В чертеже (параметры: сначала строка, потом число):
void RegisterUser(string name, int age) { ... }

// При вызове (аргументы):
RegisterUser("Иван", 25); // Правильно! "Иван" пойдет в name, 25 в age.
RegisterUser(25, "Иван"); // ОШИБКА! Робот на конвейере не сможет засунуть число в строковый карман.
```

## 6. Как устроена память: Стек, Куча и Папки

### Пространства имен (Namespace)
**Аналогия:** Представь дерево папок в Linux или Windows. У тебя может быть файл `photo.jpg` в папке `/Home/Documents/` и точно такой же файл `photo.jpg` в папке `/Trash/`. Компьютер не путается, потому что у файлов разные полные пути.

**Namespace** в коде — это и есть такие "виртуальные папки" для классов, чтобы они не конфликтовали, если два программиста назовут свои классы одинаково (например, класс `User`).

### Стек против Кучи (Stack vs Heap)
Память приложения делится на два абсолютно разных лагеря:

1. **Стек (Stack) — Стопка тарелок.**
   Ооочень быстрая память. Работает строго: последнюю тарелку положил сверху — первую её же и заберешь. Там хранятся **значимые типы** (простые числа `int`, `double`, `bool`) и локальные переменные внутри функций. Как только функция отработала, вся её "стопка тарелок" мгновенно и автоматически выбрасывается из памяти.
2. **Куча (Heap) — Огромный склад Amazon.**
   Там хранятся большие и сложные объекты (**ссылочные типы**: классы, массивы, строки). Память там выделяется хаотично, где нашлось свободное место.

### Значимые и Ссылочные типы. Что такое ссылка?
* **Значимый тип (`int`, `byte`...)**: Переменная лежит в Стек-памяти и **сама является коробкой с числом**. Копируя её, ты создаешь новую независимую коробку.
* **Ссылочный тип (Классы)**: Сам огромный объект создается в **Куче**. А в Стеке создается маленькая переменная-ссылка.
  * **Что такое ссылка?** Это просто обычное **число**, в котором записан **адрес** (номер ячейки) на складе-Куче. 

```csharp
// Создаем объект в Куче. В стеке в переменную 'myCar' запишется просто адрес, например "ячейка №4012"
Car myCar = new Car(); 
```

### Сборщик мусора (Garbage Collector / GC)
В стеке память чистится сама. А в Куче (на складе) коробки могут оставаться брошенными. 
Если мы удалим переменную-ссылку из Стека, сам объект в Куче останется лежать, но мы потеряли его адрес и больше не можем к нему обратиться. Это мусор.

**GC (Garbage Collector)** — это робот-уборщик. Он периодически включается, пробегает по Стеку, смотрит, на какие адреса в Куче еще есть "указатели". Если он видит в Куче объект, на адрес которого никто из Стека больше не ссылается, он его безжалостно уничтожает и освобождает место на складе.

### Область видимости (Scope)
Ограничена фигурными скобками `{ }`. Переменная живет только внутри своих скобок.
```csharp
{
    int x = 10; // x родился
    Console.WriteLine(x);
} // x УМЕР. Фигурная скобка закрылась, стек очистил память под x.
// Тут переменной x больше не существует, обратиться к ней нельзя.
```

## 7. Главное правило: Мы управляем Переменными, а не Типами!

Это ключевая концепция, которую нужно осознать:

* **Переменная** — это физическая, осязаемая коробка, созданная в памяти компьютера. В ней лежат биты. Мы можем брать эту коробку, менять в ней нули на единицы, переименовывать её, заглядывать внутрь. **Мы управляем и командуем именно переменными.**
* **Тип данных** — это **призрак, идея, инструкция**. Его физически нет в памяти. Тип данных — это просто "наклейка" на коробку-переменную, которая сообщает компилятору две вещи:
  1. Какого размера должна быть эта коробка в байтах (`int` — 4 байта, `byte` — 1 байт).
  2. По какому правилу читать биты внутри (как обычное число, или как число со знаком, или как дробь).

**Аналогия:** Тип данных — это рецепт супа (чертеж), а Переменная — это кастрюля с налитым супом у тебя на плите. Ты не можешь съесть рецепт или налить его в тарелку. Ты работаешь только с кастрюлей (переменной), используя правила из рецепта (типа данных).
```csharp
// Мы сказали компилятору: "Используй инструкцию 'int', чтобы создать коробку 'score' и положи туда 100"
int score = 100; 

score = 200; // Мы управляем переменной score (меняем ее содержимое). Тип int при этом никак не изменился.
```
## 8. Массивы (Array) — Многоквартирные дома для данных

Когда тебе нужно сохранить 100 чисел, создавать 100 отдельных переменных-коробок вроде `int score1`, `int score2` — это безумие. Для этого придумали **массивы**.

**Аналогия:** Массив — это длинный многоквартирный дом, где все квартиры одинакового размера, а на подъезде висит общий номер дома (название массива). 

### Главные правила массива:
1. **Фиксированный размер.** Нельзя построить дом на 5 квартир, а потом внезапно заселить туда 6-го жильца. Чтобы расширить массив, придется строить новый, более длинный дом и переселять всех туда.
2. **Один тип данных.** Все квартиры в доме предназначены для одного типа "жильцов". Нельзя создать массив, где первая ячейка — число `int`, а вторая — строка `string`.
3. **Нумерация с нуля.** В программировании квартиры (индексы ячеек) всегда нумеруются с **0**, а не с 1. В доме на 5 квартир номера будут: `0, 1, 2, 3, 4`.

### Как массив устроен в памяти (Стек и Куча)
Массив — это **ссылочный тип данных**. 
* Сам "многоквартирный дом" (все ячейки с данными) строится на большом складе — в **Куче**. Причем все ячейки выделяются в памяти строго друг за другом, плотным монолитным блоком.
* В **Стеке** лежит только маленькая переменная-перевозчик, внутри которой записан **номер ячейки (адрес)** этого дома в куче.

### Пример кода (C#)
```csharp
// 1. Бронируем в Куче дом на 3 квартиры для чисел int. 
// Переменная prices в стеке просто запоминает адрес этого дома.
int[] prices = new int[3]; 

// 2. Заселяем жильцов по индексам (номерам квартир)
prices[0] = 150; // Первая квартира (индекс 0)
prices[1] = 300; // Вторая квартира (индекс 1)
prices[2] = 500; // Третья квартира (индекс 2)

// 3. Пытаемся заселить четвертого жильца в дом из 3 квартир:
prices[3] = 900; // ОШИБКА! Программа упадет (IndexOutOfRangeException) — такой квартиры нет!

// 4. Быстрое создание и заполнение массива (Литерал массива)
string[] players = { "Иван", "Ольга", "Пётр" }; 
```

### Как `while` или `for` дружат с массивами
С помощью циклов можно автоматически обойти все квартиры в доме, зная его длину (`Length`):

```csharp
int[] Inventory = { 10, 20, 50, 5 };
int index = 0;

// Цикл будет работать, пока индекс меньше, чем количество элементов (4)
while (index < Inventory.Length) 
{
    // Выводим вещь из текущей квартиры
    Console.WriteLine($"Предмет №{index}: содержит {Inventory[index]} золота.");
    
    index = index + 1; // Переходим к следующей квартире
}
```

### Задача 3. Прыжки через один (Проход нечетных чисел в цикле)
**Условие:** Тебе нужно вывести в консоль все **нечетные** числа в диапазоне от 1 до 10 включительно (то есть: 1, 3, 5, 7, 9).
